## LoL (PC) に持ち越せる考え方

LoL では「事実」（キル・デス・オブジェクト・ゴールド）を Riot API が正解として返すので、
このフォーマットの L0 / L1 は不要になる。一方、以下はタイトルに関係なく使える:

- **`must_not_claim`** — 捏造の直接テスト。コーチング出力の評価にもそのまま使える
- **`confidence: ambiguous`** — ラベラー自身が迷うケースを採点から外す
- **段階的ラベリング** — 深さと件数を別々に選べるようにする
- **L2 の判定手順** — 最初の数件を人手で判定し、その結果で LLM-as-judge を校正してから自動化する
- **エッジケースを意図的に入れる**

## 1. 前提: 観測できる範囲

入力はプレイヤー自身の視点の録画。取れる情報には構造的な上限がある。

| 取れる | 取れない |
|--------|---------|
| 自分の HUD（HP / マナ / ゴールド / CS / レベル / アイテム / CD） | 視界外・霧の中の出来事 |
| キルフィード（全プレイヤーのキル・デスが時刻付き） | 敵ジャングラーの位置・パス |
| オブジェクト取得の全体アナウンス | 味方・敵の意図 |
| ミニマップ（味方は常時 / 敵は視界内のみ） | 操作精度、ping |
| スコアボード（開いている間だけ） | 非表示中の他人の CS / ゴールド |
| リザルト画面（全員の最終データ） | — |

人手のラベラーも同じ情報しか持たないので、正解が well-defined になる。
「敵ジャングラーが上に寄っていた」は事実ではなく推論なので、正解に書かない。

## 2. 知覚層が検出すべきもの

**A. 試合メタ（リザルト画面）** — 勝敗 / 試合時間 / 自分のチャンピオンとロール /
両チーム 10 人のチャンピオン / 全員の最終 KDA・CS・ゴールド・与ダメ・被ダメ / 最終ビルド / パッチ。
一度取れば確定し、時系列側の検算に使える（キルフィードから数えたデス数がリザルトと合わなければ取りこぼし）。

**B. 時系列骨格（N 秒ごとの HUD サンプリング）**

- ゲーム内時刻（最重要。動画時刻とゲーム内時刻の対応付けに必須）
- 自分のレベル / 所持ゴールド / CS / KDA / 保有アイテム
- アルティメット・サモナースペルの使用可否
- 自分のミニマップ位置（ゾーン粒度）
- チームゴールド差（スコアボード表示中のみ。取れない区間は欠損として明示）

**C. イベント（時刻付き）**

- 直接観測: キル / デス / アシスト / タワー / インヒビター / ドラゴン / ヘラルド / バロン /
  リコール / レベルアップ / アイテム購入
- 算出: ゴールド差の急変点 / 集団戦のまとまり / デッドタイム（機会損失）

**D. キーモーメントの選び方**（クリップにする優先順）

1. 自分のデス（全件）
2. 自分が関わった集団戦
3. オブジェクト戦
4. ゴールド差が大きく動いた瞬間
5. 長いデッドタイム

**E. 言語化の内容** — 状況 / 経過（±30 秒）/ 因果 / プレイヤーが持っていた情報。
見えていない情報に反応しなかったことは責められない。

**境界: 知覚層は「何が起きたか」と「何が見えていたか」まで。**
「悪手だった」「代わりに何をすべきか」は推論層。混ぜると評価できなくなる。

**F. スコープ外** — 敵ジャングラーの位置推定 / 全員のミニマップ位置の追跡 / 操作精度 / 複数試合の傾向分析

## 3. 段階的ラベリング

全部をラベリングすると 1 試合数時間かかり、数十件に届かない。深さと件数を別々に選べるようにする。

| Lv | 内容 | 目安 / 試合 | 用途 |
|----|------|------------|------|
| L0 | 最終スコアボード + 全キル / デス / オブジェクトの時刻 | 15〜30 分 | イベント検出の再現率・適合率。これだけで方式 A / B の比較ができる |
| L1 | 時系列骨格のサンプル点（1 分刻み） | +15 分 | 数値読み取り（OCR）の誤り率 |
| L2 | キーモーメントごとの人手の言語化 | +30〜60 分 | 言語化の品質 |

スパイクは 1〜2 試合を L0 + L1、そのうち 3〜5 モーメントだけ L2。将来の数十件は大半を L0 にする。

## 4. スキーマ

YAML で書き、JSON Schema で検証する。

```yaml
schema_version: 1
match_id: "001"

video:
  file: "001.mp4"            # Git 管理外。sha256 でラベルとの対応を保証する
  sha256: "a1b2…"
  duration_sec: 1123
  resolution: "2340x1080"
  device: "iPhone 15 Pro"
  hud_scale: default
  language: ja
  includes_result_screen: true   # false なら確定 ground truth が無いケース

labeler: h.kawai
labeled_at: "2026-08-22"
label_level: L1                 # L0 / L1 / L2

# 動画時刻とゲーム内時刻の対応。複数点置いてズレを検出する
time_anchors:
  - { video_sec: 12.5,  game_clock: "00:00" }
  - { video_sec: 620.0, game_clock: "10:07" }

match_meta:
  result: win
  duration: "18:43"
  self: { champion: lucian, role: mid }
  teams:
    ally:  [lucian, ...]
    enemy: [...]

# ---- L0 ----
final_scoreboard:
  - { champion: lucian, side: ally, is_self: true,
      kills: 8, deaths: 3, assists: 5, cs: 178, gold: 12400, damage_dealt: 34100 }

events:
  - id: e01
    type: death                # kill / death / assist / dragon / baron / herald / turret / inhibitor
    game_clock: "07:12"
    video_sec: 444.5
    subject: lucian
    counterpart: [zed]
    zone: mid_river            # 語彙は knowledge 由来（未確定。§8）
    source: kill_feed          # 何から読み取れるか = 検証できる根拠
    confidence: certain        # certain / ambiguous（ambiguous は採点から外す）

# ---- L1 ----
timeline_samples:
  - game_clock: "05:00"
    video_sec: 312.0
    self: { level: 7, gold_held: 1250, cs: 42, k: 2, d: 0, a: 1 }
    team_gold_diff: 850
    scoreboard_visible: true   # false のとき team_gold_diff は null

# ---- L2 ----
key_moments:
  - event_id: e01
    reference_narration: |
      ミッドで CS を取りに前に出た直後、川からゼドが接近。
      味方ジャングラーは下レーン付近、リコール直後で戻れない位置。
      フラッシュは 20 秒前に使用済みで使えない。
    player_had_info:
      enemy_jungler_visible: false
      minimap_warning: false
    must_not_claim:            # 捏造検出用。これを言ったら誤り
      - "フラッシュを持っていた"
      - "味方が近くにいた"
```

設計の意図:

- **`source`** — 何から読み取れるはずかを書いておくと、失敗したときに段①（OCR）と段③（LLM）の
  どちらが悪いか切り分けられる
- **`confidence: ambiguous`** — 微妙なケースを採点から外す。無いとラベラー自身の迷いでスコアがぶれ、改善の判断ができない
- **`must_not_claim`** — 捏造を直接テストする。最上位リスク（もっともらしい嘘）を名指しで測る

**このフォーマットは実装方式に依存しない。** どの方式の出力もこの形に揃えて突合する。

## 5. 採点

時刻の許容誤差を先に決めないと採点の意味が無い。キルフィードは実際の死亡から 1 秒ほど遅れて出るので、
**±2 秒** を推奨する。

| Lv | 指標 | 判定 |
|----|------|------|
| L0 | イベント検出の再現率 / 適合率 | type + subject が一致し、時刻が ±2 秒以内 |
| L0 | スコアボード読み取りの誤り率 | 整数なので完全一致のみ |
| L1 | 数値読み取りの誤り率 | 項目別に集計する（ゴールドだけ弱い、などが見える） |
| L2 | 事実誤りの有無 | **1 つでもあれば fail** |
| L2 | 因果の妥当性 / 網羅性 | 3 段階の rubric |
| L2 | 捏造の数 | 正解に無いエンティティ・数値の個数 |

L2 は最初の 2 件を人手で判定し、その結果で LLM-as-judge を校正してから自動化する。
最初から自動化すると judge 自体が正しいか検証できない。

## 6. エッジケース

頑健性が未知数なので、正常系だけでは意味が無い。意図的に入れる:

- スコアボードを一度も開かない録画
- リザルト画面が含まれない録画（`play-narration.md` FR-6 の劣化パス）
- 低解像度・低ビットレート / HUD スケールが既定でない
- 途中で切れている録画
- サレンダーで短い試合 / 極端に長い試合
