# 要求整理: プレイ行動の言語化（知覚層）

- **Date**: 2026-08-19
- **Status**: Draft（スパイク結果を受けて数値目標を確定する）
- **関連**: ADR-0002（動画のみ入力）/ ADR-0003（Gemini で言語化）/ ADR-0007（パイプライン化・Proposed）

2026-08-19 のコンセプト議論を要求として整理したもの。

## コンセプト

プレイヤーが試合動画をアップロードすると、AI がプレイを振り返ってコーチングする。
このプロダクトの品質は **知覚層（動画 → 何が起きたか）の精度が上限を決める**。
「何が起きたか」が間違っていれば、その上のフィードバックがどれだけ流暢でも無価値であり、
むしろ有害になる。

### 最重要の品質要求: もっともらしい嘘を出さない

LLM は読み取れない情報を自信満々に補完する。フィードバック内の数値・事実の誤りが 1 つでも
ユーザーに見つかると、プロダクト全体への信頼が失われる。これはコーチングプロダクト固有の
致命的リスクとして扱う。

- **事実（数値・イベント）と解釈（因果・判断）を分離する。** 事実は決定論的な手段で取り、
  LLM には解釈だけをさせる
- 事実に接地できない解釈は行動ログに載せない（推論層に引き渡さない）

## ユーザーストーリー

- プレイヤーとして、試合動画をアップロードすると重要な場面（デス、オブジェクト、集団戦）ごとに
  「何が起きたか」を正確に振り返れる。それにより自分では気づけない改善点の根拠が得られる
- プレイヤーとして、フィードバックの各指摘から動画の該当時刻にジャンプできる。
  それにより指摘を自分の目で確認できる（→ FR-2 の根拠）

## 機能要求

### FR-1: 行動ログは 2 層構造

| 層 | 内容 | 生成手段 |
|----|------|---------|
| 確定データ層 (facts) | 最終スコアボード、時系列骨格（ゴールド / KDA / タイマー）、イベント（デス / キル / オブジェクト） | 決定論的抽出（OCR 等）。LLM を使わない |
| 解釈層 (narrative) | 各キーモーメントに至る因果の言語化 | LLM。必ず facts のイベントとタイムスタンプに紐づける |

### FR-2: 全イベント・全 narration にタイムスタンプ必須

動画内時刻（可能ならゲーム内時刻も）を持つ。用途は 3 つ:
フロントの動画シーク連動、評価時の正解との突合、確定データ層との整合性検証。

### FR-3: エンティティ語彙の制約

チャンピオン名・アイテム名・オブジェクト名は `knowledge` モジュール由来の語彙（enum）に制約する。
LLM に自由文でエンティティ名を生成させない（捏造・表記ゆれの防止）。

### FR-4: 整合性検証

解釈層の出力は確定データ層と機械的に突合する。矛盾（デス数の不一致等）がある narration は
棄却または再試行し、そのまま推論層に流さない。

### FR-5: 中間成果物をすべて保存する

抽出フレーム、OCR 結果、切り出したクリップ、narration、突合結果を保存する。
ADR-0003 の「後から学習と評価に使える形で保存する」の具体化。Phase 2 の学習データ・
評価・デバッグの全てに効く。利用規約・同意の設計とセットで行う。

### FR-6: リザルト画面を確定 ground truth として扱う

試合終了時のスコアボードはレイアウト固定・情報完全な唯一の画面。録画にリザルト画面まで
含めることを UX で誘導する（アップロード時のガイド等）。含まれない場合も解析は成立させ、
精度が落ちることをユーザーに明示する。

## 非機能要求

| 項目 | 要求 |
|------|------|
| 精度 | 評価セットに対するイベント検出の再現率・適合率を計測できること。目標値はスパイク後に設定 |
| コスト | 1 解析あたりの LLM コストを記録・可視化する。全編を高解像度で一括投入する構成を常用しない |
| レイテンシ | 非同期ジョブとして成立させる。目標: アップロード完了から結果表示まで 10 分以内（仮置き） |
| 冪等性 | 同一動画の再解析で二重課金しない（ADR-0003） |
| 頑健性 | 端末解像度・録画品質・HUD スケール設定のばらつきへの耐性。**現時点で未知数 → スパイクで確認** |

## 評価要求

- 人手で正解を付けた評価セットを持つ。まず 1〜2 試合から始め、将来数十件に育てる
  （Roadmap Phase 2「評価セットを作る」の前倒し）
- 正解の形式: イベントログ（デス / キル / オブジェクトの時刻と関与者）、時系列骨格のサンプル点
- 指標:
  - イベント検出の再現率・適合率
  - 数値読み取り（ゴールド / KDA / タイマー）の誤り率
  - narration の事実誤りの有無（人手判定）

## MVP スコープ

**In**: 自分視点の 1 試合の録画（mp4）/ 1 試合単位の振り返り / 推論層が扱える構造化行動ログ

**Out**: リアルタイム解析 / 他プレイヤー視点の解析 / 複数試合をまたぐ傾向分析（将来）
