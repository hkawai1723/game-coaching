# ADR-0012: 最初の対象タイトルを LoL (PC) にし、Wild Rift を保留する

- **Status**: Accepted
- **Date**: 2026-10-07
- **Deciders**: h.kawai

## Context

ADR-0001〜0011 は Wild Rift（モバイル版 LoL）を最初の対象タイトルとして書かれている。
LoL (PC) は CLAUDE.md ロードマップの Phase 3 に置き、`MatchSource` port と `GameTitle` で
拡張の余地だけ残していた（ADR-0002）。

2026-10-07、**最初に LoL (PC) のコーチングを作る**と方針を変えた。Wild Rift は当分やらない
（廃止ではなく保留）。

**事実:**

- **LoL (PC) には Riot の公式 API がある。** `match-v5` で試合結果を、
  `match-v5` の timeline で時系列データを取得できる。
  - timeline のフレームは 1 分間隔。各フレームに全 10 人のゴールド・経験値・レベル・CS・
    ステータス・マップ座標が入る
  - イベントはミリ秒単位の時刻付き。キル（座標・関与者・与被ダメージ内訳付き）、
    アイテム購入 / 売却、スキルレベルアップ、ワード設置 / 破壊、エピックモンスター、
    建物破壊など
- Wild Rift で動画解析パイプライン（ADR-0007）を作る理由だった
  「事実（数値・イベント）を決定論的に取る」は、**LoL では API がそのまま担う。**
  OCR も Gemini の動画理解も無しで確定データ層（`play-narration.md` FR-1）が手に入る
- LoL (PC) の静的データ（チャンピオン / アイテム / ルーン / パッチ）は Riot 公式の
  **Data Dragon** で配布されている。ADR-0009 で「Wild Rift には一次情報源が無い」とした問題は、
  LoL では生じない
- LoL (PC) 向けの MCP サーバーは既に複数ある（ADR-0009 の調査結果）
- コードベースに Wild Rift 固有の実装はまだ無い。Wild Rift を前提にしているのはドキュメントだけ

**推測（未確認。実装前に確認する）:**

- Riot の Developer Policies 上、コーチング用途で有料サービスとして提供できるか、
  その条件（無料枠の要否など）は**未確認**
- Production API Key と RSO（Riot Sign On）の審査は、申請してみないと期間も通過条件も分からない
- API から取得したデータを後から学習・評価に使うために保存・二次利用できる範囲は、
  利用規約の確認が要る

## Decision

### 1. 最初の対象タイトルは LoL (PC)。Wild Rift は保留する

- 同じリポジトリ・同じモジュール構成のまま進める。リポジトリは分けない
- Wild Rift 向けの ADR は書き換えずに残し、ステータスを付け替える（下表）

| ADR | 新しい Status | 理由 |
|-----|--------------|------|
| 0002 動画のみ入力 | **Superseded by ADR-0012** | プロダクトの入力経路の決定そのものが変わる |
| 0003 動画の言語化に Gemini | **Deferred** | 動画を入力にする時点（Wild Rift 再開、または LoL で動画を足す時）に有効。今は動画を扱わない |
| 0007 知覚層パイプライン | **Deferred**（Proposed のまま保留） | 同上。スパイクは実施しない |
| 0009 Wild Rift ナレッジ自作 | **Deferred** | Wild Rift の判断としては今も正しい（LoL データを WR に流用しない）。再開したらそのまま効く |

0001 / 0004 / 0005 / 0006 / 0008 / 0010 / 0011 はタイトルに依存しないので、そのまま有効とする。

### 2. Phase 1 の試合データ入力は Riot API

- `MatchSource` の最初の実装を `RiotApiMatchSource` にする（`match-v5` + timeline）
- **動画は Phase 1 で扱わない。** `VideoMatchSource` は書かない
- `GameTitle` 値オブジェクト（`LOL` / `WILD_RIFT`）はそのまま残す。Wild Rift の再開口になる

### 3. Phase 1 の LLM は推論層（コーチング生成）だけにする

- 行動ログ（「何が起きたか」）は API のデータから **決定論的に** 組み立てる。LLM を使わない
- LLM を使うのは `coaching`（「どうすべきだったか」）だけ
- ADR-0007 の原則「事実は決定論で取り、LLM には解釈だけさせる」は、より強い形で満たされる

### 4. ナレッジは Riot 公式の Data Dragon を一次情報源にする

- 静的データの自作スクレイピングはしない
- 取得手段の詳細と、MCP にするかどうかは `knowledge` のデータモデル設計で決める
  （CLAUDE.md Open Decisions #2）

## Consequences

### 良くなること

- **知覚層のリスクが消える。** プロダクトの品質上限を決めていた
  「動画から事実を正しく取れるか」が、検証済みの公式 API に置き換わる
- 試合ごとのコストが下がる。動画の保存・転送も、マルチモーダル LLM への動画入力も無くなる。
  LLM コストは推論層の分だけになる（Open Decisions #6 の課金モデルが設計しやすくなる）
- 「録画してアップロードする」手間が無くなる。Riot ID かアカウント連携だけで試合が取れる。
  `coaching-quality.md` の「価値 = 品質 × 利用頻度」の利用頻度側に効く
- 戦闘計算（ADR-0010 / 0011）に入力が揃う。timeline のアイテム購入とレベルアップから
  **任意の時刻のビルドとレベルを復元できる**。Wild Rift で問題だった
  「その時点の敵ビルドが観測できない」が消える
- ADR-0011 の手順 A（効果語彙の洗い出し）の前提だった「データ源の調査」が、
  Data Dragon でほぼ片付く
- 評価セットのうち「事実」の部分は API が正解になる。人手のラベリングは
  コーチング品質（`coaching-quality.md` の rubric）に集中できる

### 悪くなること / 引き受けるリスク

- **Riot の規約と審査に依存する。** Production Key と RSO の審査に通らなければ本番を出せない。
  Developer Key は 24 時間で失効し、レート制限も厳しいので開発専用
- **API のデータは全知視点で、プレイヤーの視点ではない。** timeline には敵ジャングラーの座標も入っているが、
  プレイヤーにそれが見えていたかは分からない。`coaching-quality.md` FR-5
  （見えていた情報でのみ評価する）をそのまま守れない。
  「データには載っているがプレイヤーには見えていなかった情報」で責めない設計が要る
- **時系列の粒度が粗い。** フレームは 1 分間隔なので、集団戦のスキルの撃ち合いや位置取りは取れない。
  ミクロ（操作・位置取り）のコーチングは Phase 1 の範囲外になる
- 競合が多い。LoL (PC) には API を使った分析サービスが既に多くある。
  差別化は統計の量ではなく、`coaching-quality.md` のコーチング品質
  （絞り込み、宿題の機械検証、意図の入力）で取る必要がある
- Wild Rift 向けの上流工程の成果（ADR-0007 のパイプライン、評価セットのフォーマット）が当面寝る

### この決定を覆すときのコスト

低い。Wild Rift を再開するときは、Deferred の ADR を見直して `VideoMatchSource` を足す。
`MatchSource` port と `GameTitle` のおかげで、`match` より下流は書き換えずに済む設計を保つ。
Wild Rift 向けの評価セットのフォーマットは `docs/analysis/design/eval-set-format.md` に保留で残してある。

## Alternatives Considered

| 案 | 却下理由 |
|----|---------|
| LoL 用に別リポジトリを作り直す | Wild Rift 固有のコードがまだ無く、モジュール構成・認証・決済・テスト方針はタイトルに依存しない。分ける利点が無く、設計の履歴が 2 か所に割れる |
| Wild Rift の ADR を削除・書き換えする | ADR の運用ルール（書き換えず Superseded にする）に反する。再開時に「なぜそう決めたか」が失われる |
| LoL でも動画解析を主な入力にする | API で正確な事実が取れるのに、精度の劣る経路を主にする理由が無い。ミクロのコーチング用に動画を足すのは、Phase 1 の後に別 ADR で検討する |
| Wild Rift と LoL を同時に進める | 知覚層（動画）と API 連携という性質の違う 2 つの基盤を同時に作ることになる。まず API で「使えるコーチング」の基準を作るのが先 |
