# ADR-0015: MVP で録画も入力にし、モジュールを `ingestion` / `playlog` に改名する

- **Status**: Accepted
- **Date**: 2026-10-12
- **Deciders**: h.kawai

## Context

ADR-0012 で LoL (PC) を最初の対象にし、「**動画は Phase 1 で扱わない**」と決めた。
入力は Riot API（`match-v5` + timeline）だけで、ミクロ（操作・位置取り）は Phase 1 の範囲外にしていた。

2026-10-12、**ローカル MVP（エピック COACH-5）で Riot API と録画の両方を入力にする**と決めた。
Jira のバックログ（COACH-17〜25）は、録画を前提にすでに組んである。

**事実:**

- timeline のフレームは 1 分間隔。デス前後の位置取り、スキルの撃ち合い、集団戦の動きは API では取れない
  （ADR-0012 の Consequences）
- API のデータは全知視点。プレイヤーに見えていたかは分からないので、
  `coaching-quality.md` FR-5（見えていた情報でのみ評価する）を API だけでは守れない
- 録画には、プレイヤーの画面に映っていたもの（視界・ミニマップ・HUD）がそのまま残っている

モジュール名にも問題があった。`match`（試合の受付）と `analysis`（行動ログ化）は名前が漠然としている。
「`match` で Gemini が動画を解析し、`analysis` が Riot API を叩く」と、役割を逆に読み違えることが実際に起きた。
しかも、録画を足すと「解析」の意味がさらに広がる。

## Decision

### 1. MVP の入力は Riot API と録画の 2 本にする

- **事実（キル・時刻・ゴールド・アイテム等）は Riot API が正。** 録画から取ったもので上書きしない
- 録画を使うのは、API で取れないものに限る:
  - プレイヤーに見えていた情報（FR-5 の `player_had_info`）
  - デス前後のミクロ（位置取り、直前の行動、スキル・サモナースペルの使用状況）
  - 集団戦での動き
- **録画は任意。** 録画が無い試合でも、Riot API のデータだけでコーチングが返る
- 録画は試合を受け付ける経路ではなく、Riot API の試合を補う入力にする。
  そのため `MatchSource` の実装にはしない（ADR-0012 で想定していた `VideoMatchSource` とは別物）

### 2. モジュールを改名する

| 旧 | 新 | 責務 |
|----|----|------|
| `match` | **`ingestion`** | 外部から試合の入力を取り込む。Riot API からの取得（`MatchSource`）、録画のアップロードと試合への紐付け、生データの保管、解析ジョブの状態管理 |
| `analysis` | **`playlog`** | 取り込んだ入力から行動ログ（`PlayLog`）を組み立てる。timeline からの決定論的な組み立てと、録画の理解（動画理解の port）の統合 |

- 名前は、そのモジュールが作るもの・やることで付ける。`ingestion` → `playlog` → `coaching` の順に、
  前のモジュールが作ったものを次のモジュールが使う
- Riot API の生データ（match + timeline の JSON）は `ingestion` が保管する。`playlog` は ID で受け取って解釈する。
  再解析で Riot API を叩き直さないため
- 録画と試合時刻の同期・クリップの切り出し（COACH-19）は `ingestion` に置く。これらは決定論的な前処理で、
  プレイの解釈をしないため
- 録画の中身を言語化する（COACH-20〜22）のは `playlog`。行動ログに「動画由来」と区別して足す
- ADR-0001〜0014 は書き換えない。そこに出てくる `match` は `ingestion` を、`analysis` は `playlog` を指す
  （ドキュメントのパスだけは `docs/ingestion/` / `docs/playlog/` に直した）

### 3. この ADR で決めないこと（COACH-17 で決める）

以下は COACH-17 で別の ADR に記録する（CLAUDE.md Open Decisions #10）。

- 動画理解の方式: 場面単位のクリップをマルチモーダル LLM に渡すか、決定論的な知覚層（ADR-0007）にするか。
  バックログは前者を想定している
- 動画理解に使うモデル（コーチング生成の Gemini と同じでなくてよい。ADR-0013）
- 動画理解の port の名前と形（ADR-0003 の `PlayNarrator` を流用するか、`SceneNarrator` 等にするか）
- 録画の保存先（MVP はローカルの Docker volume の想定。Open Decisions #4）
- 1 試合あたりのコスト見積もり
- ADR-0003 / 0007 の Deferred を解除するか、新しい ADR に置き換えるか

### ADR-0012 との関係

ADR-0012 の Decision 2「**動画は Phase 1 で扱わない**」と Decision 3「**Phase 1 の LLM はコーチング生成だけ**」を、
この ADR で改める。それ以外（LoL を最初の対象にする、Wild Rift を保留する、事実は Riot API を正にする、
Data Dragon を使う）はそのまま有効。

## Consequences

### 良くなること

- ミクロのコーチングが MVP の範囲に入る。Riot API の統計だけを使う既存サービスとの差別化になる
- FR-5 を守る手段ができる。録画があれば「見えていたか」を判定でき、無ければ「不明」として控えめに扱える
- 録画の言語化に API の事実（時刻・キラー・関与者）を渡せるので、動画理解の誤りを抑えられる
  （ADR-0007 の「決定論で接地する」が、知覚層を作らなくても API で満たせる）
- モジュール名から、データの流れと LLM を使う場所が読める

### 悪くなること / 引き受けるリスク

- MVP の期間が延びる。バックログ上は Sprint 5〜8 の 4 週間が録画の分（期日 2026-12-06）
- 試合ごとのコストが上がる。動画理解の呼び出しと、録画の保存・転送が増える
- 録画とゲーム内時刻の同期（COACH-19）が新しい不確実性になる。無編集の録画を前提にし、手動入力に逃げられるようにする
- 動画理解の誤りがコーチングに混ざるリスクが戻ってくる（ADR-0012 で消えたリスクが部分的に戻る）。
  事実は API を正にし、動画由来の情報は区別して持つことで抑える
- 録画のアップロードという手間がユーザーに増える。録画を任意にすることで、利用頻度への影響を抑える

### この決定を覆すときのコスト

低い。録画は任意の補足入力で、行動ログでも動画由来の部分を区別して持つ。
録画をやめても、`ingestion` のアップロード経路と `playlog` の動画理解 port を外すだけで、
Riot API だけの経路はそのまま動く。

モジュール名の変更は、コードがまだ無い今がいちばん安い。

## Alternatives Considered

| 案 | 却下理由 |
|----|---------|
| 録画は Phase 1 の後に回す（ADR-0012 のまま） | 自分で使ってみて差が出るのはミクロと FR-5。API だけの MVP では既存サービスとの違いを確かめられない |
| 録画を `VideoMatchSource` として `MatchSource` の実装にする | 録画は試合を受け付ける経路ではなく、API の試合を補うもの。事実の出どころが 2 つになり、どちらが正か曖昧になる |
| 動画の知覚層を `perception` という別モジュールにする | MVP の動画理解は場面ごとに LLM へ渡す想定で、行動ログに足す情報を作るだけ。別モジュールにする理由がまだ無い。決定論的な知覚層（ADR-0007）を作るときに見直す |
| 名前を `match` / `analysis` のまま残す | 実際に役割を読み違えた。録画が入ると「解析」がどこを指すかがさらに曖昧になる |
| `match` を `intake` / `retrieval` にする | `intake` は ingestion とほぼ同じ意味で、一般的な ingestion を選んだ。`retrieval` は API から取ってくることに寄った名前で、録画のアップロードに合わない |
| `analysis` を `timeline` / `reconstruction` にする | `timeline` は Riot の timeline と紛らわしく、録画由来の情報を含められない。作るもの（`PlayLog`）の名前に揃えた |
