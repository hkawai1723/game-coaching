# テスト仕様書フォーマット

ブラックボックス E2E テスト仕様書の Markdown フォーマット定義。
テスターが GUI 操作で実施する手動テスト向け。CSV エクスポートスクリプトでパース可能な構造。

## フォーマット

````markdown
# テスト仕様書: <タイトル>

## メタ情報

| 項目 | 値 |
|------|-----|
| 対象機能 | <対象機能の説明> |
| ブランチ | <feature-branch> |
| ベースブランチ | <main / develop> |
| 作成日 | <YYYY-MM-DD> |
| 変更概要 | <変更内容の要約> |

## テストケース

### TC-001: <テストケース名>

| 項目 | 内容 |
|------|------|
| カテゴリ | 正常系 |
| 優先度 | High |
| 画面 | <画面名> |
| 前提条件 | <前提条件。なければ「なし」> |
| 操作概要 | <ユーザーが行う操作の概要> |
| 期待結果 | <画面上で確認できる結果> |
| テスト手順 | -- |
| 備考 | <補足情報。なければ「なし」> |
````

## フィールド定義

### テストケース ID

- `TC-XXX` の 3 桁ゼロ埋め連番
- テスト仕様書全体で一意

### カテゴリ

| 値 | 説明 |
|---|------|
| 正常系 | 正常な入力・操作による期待通りの動作 |
| 異常系 | 不正入力・エラー発生時の挙動 |
| 境界値 | 上限・下限・空・最大文字数等の境界条件 |
| セキュリティ | 認証・認可・不正アクセス等 |

### 優先度

| 値 | 説明 |
|---|------|
| High | 必須。リリースブロッカー |
| Medium | 推奨。主要なユースケース |
| Low | あると望ましい。エッジケース |

### 画面

- ユーザーが操作する画面の名称
- 設計書（`docs/*/design/screen-transition.md` 等）の画面名と一致させる

### 操作概要

- generate-test-case が記載する抽象的な操作の説明
- 例: 「有効な情報でデッキを新規作成する」
- 具体的な GUI 操作手順は generate-test-procedure が後から埋める

### テスト手順

- generate-test-case 段階では `--`（未記入マーカー）
- generate-test-procedure がコード調査後に具体的な GUI 操作手順を記入
- 番号付きリストで記述し、テーブル内では `\n` で改行を表現
- 例: `1. ホーム画面の「デッキ作成」ボタンをタップする\n2. デッキ名に「テスト」と入力する\n3. 「保存」ボタンをタップする`

### 期待結果

- テスターが画面上で確認できる検証可能な条件
- 「正しく動作する」のような曖昧な表現は禁止
- 例: 「デッキ一覧画面に遷移し、作成したデッキが一覧に表示される」

## テストケース導出の観点

### 変更種別ごとの観点

| 変更種別 | テスト観点 |
|---------|----------|
| 新規画面 | 画面表示、各要素の初期状態、ナビゲーション |
| API エンドポイント追加 | 正常レスポンスの画面反映、エラー表示、ローディング |
| バリデーション追加 | 有効値、無効値、境界値、エラーメッセージ表示 |
| 既存機能の修正 | 修正後の動作確認、回帰テスト（既存動作が壊れていないか） |
| DB スキーマ変更 | データの表示・保存・更新が正常に動作するか |

### 共通観点

- **空入力・未入力** での挙動
- **最大文字数・最小文字数** でのバリデーション
- **認証状態** — 未ログイン・ログイン済み・権限不足
- **画面遷移** — 正常遷移・戻る操作・ブラウザバック
- **エラー表示** — エラーメッセージの内容・表示位置
- **レスポンシブ** — 画面サイズによる表示崩れ（該当する場合）
